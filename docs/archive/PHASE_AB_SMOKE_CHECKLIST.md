## 2. 执行前准备

### 2.1 环境准备

- 已安装 Python 3.12 左右版本
- 已安装 Node.js 18+
- 已安装项目依赖：
  - 后端：`pip install -r requirements.txt`
  - 前端：`cd frontend && npm install`
- `.env` 已正确配置
- 若要验证本地模型：
  - Ollama 服务可用
  - 至少存在一个本地模型，如 `qwen2.5:7b`
- 若要验证云端模型：
  - 已配置可用的云端 `API Key`
  - `Base URL` 与 `model` 可真实调用

推荐两终端启动：

```powershell

uvicorn api_server:app --host 127.0.0.1 --port 8000 --reload
```

```powershell
# 终端 2
cd frontend
npm run dev
```

访问地址：

- 前端开发地址：`http://localhost:5173`
- 后端接口地址：`http://127.0.0.1:8000`

## 3. Phase A 冒烟检查

### A-01 服务健康检查

步骤：

1. 浏览器打开 `http://127.0.0.1:8000/api/health`

预期结果：

- 返回 HTTP `200`
- JSON 中包含 `status: "ok"`

失败判定：

- 无法访问
- 返回 5xx
- 后端启动即报错

---

### A-02 空消息校验

步骤：

1. 在前端新建会话
2. 不输入文本、不上传图片、不上传文件
3. 直接点击发送

预期结果：

- 前端阻止发送，或后端返回明确校验错误
- 不应出现服务崩溃
- 不应出现“消息发送成功但内容为空”

失败判定：

- 空消息被正常写入会话
- 后端 500
- 浏览器控制台或后端日志出现未处理异常

---

### A-03 单模型文本对话

步骤：

1. 选择一个可用模型
2. 发送普通文本，如“你好，请用一句话介绍自己”

预期结果：

- 正常流式返回
- 最终出现单面板完成
- 页面无报错、无卡死

失败判定：

- 无响应
- 中途流断开
- 返回明显异常栈信息

---

### A-04 多模型并行对话

步骤：

1. 至少选择两个面板
2. 发送同一条普通文本，如“请分别用一句话总结企业知识库系统的作用”
3. 观察两个面板的流式输出过程

预期结果：

- 两个面板都各自输出内容
- 不会出现其中一个面板还在输出、全局却已经提前结束
- 只有在所有面板都完成后，前端整体状态才结束加载

重点观察：

- 是否出现“某面板半截停止”
- 是否出现“有面板没结束，但输入框已经解锁”

失败判定：

- 任一面板提前断流
- 全局完成时仍有面板未完成
- 页面持续 loading 不结束

---

### A-05 `auto` 模式自适应

#### A-05-1 本地 provider

步骤：

1. 面板 provider 选择 `local`
2. `agent_mode` 选择 `auto`
3. 发送一条简单问题
4. 观察后端日志

预期结果：

- 日志出现类似：
  - `[Auto] provider=local -> agent_mode=langgraph`

#### A-05-2 云端 provider

步骤：

1. 面板 provider 选择 `cloud`
2. `agent_mode` 选择 `auto`
3. 发送一条简单问题
4. 观察后端日志

预期结果：

- 日志出现类似：
  - `[Auto] provider=cloud -> agent_mode=function_calling`

失败判定：

- 本地和云端都走同一种默认模式
- 日志与 UI 选择不一致

---

### A-06 知识库基础检查

步骤：

1. 打开 `http://127.0.0.1:8000/api/knowledge-bases`
2. 查看返回的知识库列表

预期结果：

- 返回 HTTP `200`
- 返回 `knowledge_bases` 数组
- 不出现异常报错

失败判定：

- 接口 500
- 返回结构异常
- 后端日志出现导入或内部异常

---

### A-07 RAG 参数校验

前提：

- 已有可用知识库，或先上传 `test_doc.md` / 业务测试文档

步骤：

1. 发送一个应命中知识库的问题
2. 查看后端日志中的 Rerank 输出

预期结果：

- 出现类似日志：
  - `[Rerank] query=... fetch_k=10 top_k=3 ...`

失败判定：

- 仍显示 `fetch_k=6`
- 仍显示 `top_k=2`
- 问题明明能命中知识库却没有进入 Rerank

---

### A-08 文件附件对话基础回归

步骤：

1. 上传一个小型文本文件或 Markdown 文件
2. 不输入文字，直接提问或发送“请读取附件并总结”
3. 观察返回

预期结果：

- 后端不报错
- 模型能基于附件内容回答，或至少返回明确可理解的错误提示

失败判定：

- 上传附件后直接 500
- 文件内容完全未被处理
- 发送后会话卡死
